# Уведомления о заявках

Когда посетитель отправляет форму на сайте, заявка сохраняется в базе (видна в `/admin/#/orders`)
и параллельно уходит во все настроенные каналы: **Telegram**, **MAX**, **почту**.
Каналы независимы: можно включить один, два или все три. Если канал не настроен — он пропускается;
если отправка не удалась — заявка всё равно сохранена, а ошибка пишется в лог сервера.

Все настройки — в файле `.env` (образец: `.env.example`). После изменения `.env` перезапустите сервер.

Две команды для проверки:

```bash
npm run notify:test   # отправить тестовое сообщение во все настроенные каналы и показать результат
npm run notify:ids    # показать ID чатов/пользователей, которые видит бот (Telegram и MAX)
```

Пример уведомления:

```
🆕 Новая заявка с сайта
Мастер-класс: Palermo
Имя: Анна
Телефон: +7 900 111-22-33
Гостей: 2
Комментарий: …
Все заявки: https://paprika-studio.ru/admin/#/orders
```

---

## Telegram

1. В Telegram откройте [@BotFather](https://t.me/BotFather) → `/newbot` → получите токен.
2. Куда слать:
   - **в личку** — напишите своему боту любое сообщение;
   - **в группу менеджеров** — добавьте бота в группу и напишите в ней что-нибудь.
3. Впишите токен в `.env` → `TELEGRAM_BOT_TOKEN=…` и выполните `npm run notify:ids` —
   команда покажет строку вида `TELEGRAM_CHAT_ID=-1001234567890`. Скопируйте её в `.env`.
4. `npm run notify:test` → должно прийти тестовое сообщение.

## MAX

1. Бота в MAX может создать только организация/ИП с подтверждённым профилем в кабинете
   «MAX для партнёров» (подтверждение через Госуслуги или банк). Создайте бота, дождитесь модерации,
   скопируйте токен → `MAX_BOT_TOKEN=…`.
2. Куда слать:
   - **в групповой чат** — добавьте бота в чат менеджеров → нужен `MAX_CHAT_ID`;
   - **в личку** — напишите боту сами → нужен `MAX_USER_ID`.
3. `npm run notify:ids` покажет `MAX_CHAT_ID=…` (чаты, где состоит бот) и `MAX_USER_ID=…`
   (кто писал боту). Заполните **одно** из двух.
4. `npm run notify:test`.

**Сертификат.** API MAX (`platform-api2.max.ru`) использует сертификат Минцифры, которому Node.js
по умолчанию не доверяет. В проекте уже лежит корневой сертификат `certs/russian_trusted_root_ca.pem`
(скачан с Госуслуг, gu-st.ru; SHA-256
`D2:6D:2D:02:31:B7:C3:9F:92:CC:73:85:12:BA:54:10:35:19:E4:40:5D:68:B5:BD:70:3E:97:88:CA:8E:CF:31`,
действует до 2032 года). Он используется **только** для запросов к MAX — остальной сайт его не касается.
Другой путь можно указать в `MAX_CA_FILE`.

## Почта

Нужен любой ящик с доступом по SMTP. Для Яндекса, Mail.ru и Gmail обычный пароль не подойдёт —
создайте **пароль приложения** в настройках безопасности ящика.

| Почта | SMTP_HOST | SMTP_PORT |
|---|---|---|
| Яндекс (и Яндекс 360 для домена) | `smtp.yandex.ru` | `465` |
| Mail.ru | `smtp.mail.ru` | `465` |
| Gmail | `smtp.gmail.com` | `465` |

```env
SMTP_HOST=smtp.yandex.ru
SMTP_PORT=465
SMTP_USER=zayavki@paprika-studio.ru
SMTP_PASS=пароль-приложения
MAIL_FROM=Paprika Studio <zayavki@paprika-studio.ru>
MAIL_TO=manager@paprika-studio.ru, owner@paprika-studio.ru
```

Тема письма: `Заявка №12: Анна, Мастер-класс «Palermo»`. Если сервер требует STARTTLS на порту 587 —
укажите `SMTP_PORT=587` (или явно `SMTP_SECURE=0`).

## Частые ошибки (вывод `npm run notify:test`)

| Сообщение | Что сделать |
|---|---|
| `Telegram ответил 401` | неверный `TELEGRAM_BOT_TOKEN` |
| `Telegram ответил 400: chat not found` | бот не в этом чате или неверный `TELEGRAM_CHAT_ID`; напишите боту и снова `npm run notify:ids` |
| `MAX ответил 401: Invalid access_token` | неверный `MAX_BOT_TOKEN` |
| `сервер не доверяет сертификату` | не найден сертификат Минцифры — проверьте `MAX_CA_FILE` / наличие `certs/russian_trusted_root_ca.pem` |
| `неверный логин или пароль приложения (SMTP 535)` | проверьте `SMTP_USER` и пароль приложения |
| `Таймаут подключения к SMTP` | хостинг блокирует исходящий порт 465/587 — уточните у хостинга или попробуйте другой порт |
